## What the screenshot and source establish

1. **Tasks exist in UI state but rows are clipped.** The screenshot shows `3 Open Tasks`, a Task Matrix header and add form, but no list or `No tasks found` message. `ProductivityHub.jsx` computes the count from `tasks` and maps that same array to rows. The main two-column area uses `flex-1 ... overflow-hidden`; its task panel also uses `overflow-hidden`, and the list is `flex-1 overflow-y-auto`. Above it, the timer/reminder/focus row uses substantial height. In the shown viewport, the task list appears to be reduced to zero or nearly zero height. This is a strong source-and-image diagnosis, but requires a rendered app check at the user's viewport. Fix sizing and scrolling without hiding the list behind fixed-height/clipped ancestors. Check small windows, DPI scaling, all themes, long notes, and many tasks.
2. **The question in the screenshot bypasses the offline parser.** `command_parser.py` recognizes `list my tasks`, `what tasks do I have`, and `what is due this week`, but does not match `What are my pending tasks?`. `/chat` therefore falls through to the selected LLM, which currently sees only `open_app` and `open_website` as tools. The answer asking for a calendar is wrong for VEGA's own task list. Add natural task-query variants to the deterministic path and expose a read-only task tool to optional LLMs using the same executor. Never let an LLM fabricate a task answer without reading local task state.
3. **Chat history is owned by a component that remounts.** `AIBrain.jsx` initializes `messages` with `useState([])`. `App.jsx` conditionally mounts either the Neural Cosmos module view or the normal dashboard, and hides the root with `{isVisible && ...}`. Switching between those layouts or hiding the overlay can unmount `AIBrain` and discard history. Move conversation state to an owner that survives theme/overlay switches; persist a bounded history locally if restart continuity is desired. Keep a clear-history control. Preserve messages and any in-flight response across a theme change without duplicate sends or stale voice callbacks.
4. **M1 is materially useful but its completion label needs scope.** The handoff documents deterministic actions and synthetic tests. It explicitly leaves real microphone, Windows notification rendering, and packaged installer checks unrun. The screenshot shows two user-facing M1 gaps (task visibility and natural task query), so treat M1 as code implemented with integration fixes outstanding, not fully verified in the desktop app.
5. **`README.md` is stale for M1.** Its roadmap link still says features in the plan are not implemented. Update it to distinguish implemented M1 code, manual checks still needed, and future milestones. Historical `BUILDPLAN.md` findings must be reconciled with current source before acting.

## AI Radar: what the user asked for

VEGA should research once daily for model releases, useful open/local models, genuinely free API models, and legitimate free-credit/token offers. It should show a concise digest in the dashboard and optionally notify once when there is something new and relevant. It should answer `What's new in AI today?` and `Any new free models or API credits?` from stored, timestamped results. The research requires internet; when offline, show the last successful run and its age. Do not claim a fresh search occurred.

### Source strategy at ₹0 recurring API cost

Use public, documented APIs and official announcement pages. Prefer structured feeds/APIs and GitHub releases. Poll once daily plus a user-invoked refresh; cache HTTP responses, honor timeouts/rate limits, and cap per-source work. Suggested initial adapters:

| Source | Role | Verification rule |
| --- | --- | --- |
| [GitHub public releases API](https://docs.github.com/en/rest/releases/releases) for a short configured list of projects (for example Ollama, llama.cpp, faster-whisper) | Discover versioned releases | Link to the release and use `published_at`; do not call a tag-only update a release. |
| [Hugging Face Hub search/API](https://huggingface.co/docs/hub/api) | Discover recent model repositories | A new repository is a candidate, not proof of a major model launch. Inspect the model card, publisher, license, and official announcement before labeling it. |
| [Gemini API release notes](https://ai.google.dev/gemini-api/docs/changelog) and [OpenAI news](https://openai.com/news/) | Official model/API announcements | Keep the original title, URL, and publication date. Use official model/pricing docs for availability. |
| [OpenRouter models API](https://openrouter.ai/docs/api/api-reference/models/get-models) and [free models catalog](https://openrouter.ai/collections/free-models) | Discover free hosted model availability | Confirm current model ID and current pricing/free designation. A free model is not a promotional token grant; rate limits may apply. |
| Provider's own pricing/promotion page, e.g. [Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing), [Groq limits](https://console.groq.com/docs/rate-limits), or [Qoder event pages](https://docs.qoder.com/events/newqoderlaunch) | Verify a claimed free tier or credit offer | Show exact source and checked time. Record eligibility, region, expiration, billing requirement, and quota when stated. If unknown, say `not confirmed`. Expired offers must not appear as current. |

Do not assume an official site has RSS if none is documented. A normal HTTP fetch and a small parser is acceptable when allowed by the source; handle HTML changes as source failures. Do not use Google/Bing scraping, browser automation, or a paid search API for the daily job. Community sites and Hacker News can suggest leads but cannot alone verify an offer or provider launch.

### Storage and delivery

- Add `ai_radar_items` with stable source ID/canonical URL, category (`model_release`, `local_model`, `free_api_model`, `credit_offer`, `other`), title, publisher, source URL, published/first-seen/last-checked times, summary, evidence links, verification status, and optional offer terms. Add `ai_radar_runs` with start/end, per-source counts/errors, and freshness. Add digest/read/dismiss state so the user can see past items without repeated alerts. Migrate without changing or exposing current tasks/notes.
- Normalize URLs, deduplicate across sources, and sort by publication time and user relevance, not popularity alone. Never mistake the fetch date for the announcement date. Keep summaries short and attributed; do not reproduce entire articles.
- Default to one daily check around 09:00 in the user's configured local time zone, with a user-adjustable time and an explicit `Refresh now`. Run a missed check once after restart if the last success is older than a day. Prevent duplicate jobs on dev reload/multiple app instances. A network/source failure should retain prior items and display a useful status; do not clear the feed.
- Show a compact `AI Radar` panel in the existing Data Feeds area or as an adjacent section: latest verified items, category, date, direct source link, `free` versus `limited promotion`, and freshness/last-check status. Notify at most once per daily digest, with quiet hours, mute, and no notification when nothing qualifying changed. The digest is persisted before notification.
- Support a deterministic read-only `get_ai_radar_digest` intent/tool and a `refresh_ai_radar` user action. No external provider key is required for the baseline. A local LLM summary may be optional, but the digest must still work without Ollama or Gemini. Qwen3.8-Max in Qoder is the coding model; it is not automatically a runtime research service inside VEGA.
- Treat remote content as untrusted text. It cannot instruct VEGA to call PC tools, alter settings, send messages, or spend money. Sanitize titles/HTML, validate external URLs, and only open a clicked source link.
