# Voice reliability and Hey Vega

## Purpose
Improve the owner's reported slow and inaccurate voice experience, then train and evaluate the chosen wake phrase: Hey Vega, pronounced VAY-guh.

## Current changes
The capture VAD now consumes every complete frame instead of accumulating stale speech. Worker events are marshalled to the asyncio owner. Whisper initialization is single-flight, custom asset paths are used by the loader, and lazy decoding is serialized. An explicit custom wake model fails closed instead of falling back to Jarvis.

## Evidence boundary
Synthetic tests validate these corrections. Real microphone accuracy, latency and custom wake-model quality require owner audio and native testing. No Vega model has been trained or installed. See docs/VOICE_QUALITY_AND_HEY_VEGA.md for the remaining capture lifecycle issues and training/evaluation procedure.

## Next action
Correct capture lifecycle/pre-roll and collect a consented held-out voice evaluation set. Train a versioned custom wake model using inspected upstream assets and evaluate it before activation. Keep the existing working artifact until promotion is justified.

## Learning
Wake-word detection, speech endpointing and transcription are separate stages. A renamed model file does not learn a new phrase, and a short false-wake test cannot establish a reliable hourly false-alarm rate.
