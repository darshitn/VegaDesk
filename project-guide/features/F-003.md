# Beta UI and voice implementation

## Purpose and behavior
Use the isolated workspace and interrupt spoken replies.

## Flow and responsibilities
Text/voice enters the backend; deterministic handlers run first. Optional models propose actions through the registry and policy. React refreshes committed productivity changes.

## Decisions and trade-offs
Reuse the existing Electron, React, FastAPI and SQLite application. Historical motivation is documented in the brief; this review does not establish every original decision.

## Code map
frontend/src/hooks/useChat.js
frontend/src/lib/voiceInterruption.js
frontend/src/lib/productivityUpdates.js
backend/voice_service.py

## Failure and recovery
Repeat owner voice tests when voice is enabled; ordinary beta keeps the microphone off.

## AI involvement
Runtime AI is optional; ordinary beta uses deterministic commands. Ollama integration exists but real inference is unverified in this review.

## Concept
Implementation, automated evidence and desktop acceptance answer different questions.
